Developer Documentation

Integrate PrimePay using authenticated REST APIs, idempotent payment requests and signed webhook events. This reference documents the endpoints currently exposed by the PrimePay V1 backend.

Base URL

All PrimePay V1 API routes are mounted under the following path. The production hostname is environment-specific, so keep the API base URL configurable in your integration rather than hard-coding it. 

https://YOUR-PRIMEPAY-HOST/api/v1
For local development, the backend used by the current PrimePay frontend is: http://localhost:5001/api/v1

Authentication

PrimePay uses two authentication models. Merchant dashboard operations use JWT bearer authentication. Developer API operations use an API key and API secret.

Dashboard / Merchant API JWT access token in the Authorization header.
Developer API X-API-Key and X-API-Secret headers.

JWT authentication

Authorization: Bearer YOUR_JWT_TOKEN

JWT authentication is used by authenticated merchant and administrative routes such as businesses, payments, transactions, customers and API-key management.

Developer API authentication

X-API-Key: pk_test_YOUR_KEY_ID
X-API-Secret: YOUR_API_SECRET
API secrets are returned only when an API key is created or rotated. PrimePay does not expose the secret again through the API-key listing endpoint. Store it securely when it is shown.

Supported headers

Header Required Used by
Authorization Yes for JWT routes Merchant/Admin API
X-API-Key Yes for developer API Developer endpoints
X-API-Secret Yes for developer API Developer endpoints
Idempotency-Key Yes for payment creation Payment creation
Content-Type Yes for JSON bodies JSON requests

Payments

Payments represent a customer payment request made through an active PrimePay provider. Payment creation is protected by idempotency.

POST /payments Create payment

Requires JWT authentication and an Idempotency-Key.

  "currency": "KES",
  "country": "KE",

  "customerName": "John Doe",
  "customerEmail": "john@example.com",
  "customerPhone": "+254700000000",
  "description": "Order payment",
  "metadata": {
    "orderId": "ORDER-1001"
  }

Authorization: Bearer YOUR_JWT_TOKEN
Content-Type: application/json

Payment Lifecycle

A payment does not become completed merely because a request was accepted. PrimePay maintains explicit payment states and provider verification controls the final state.

Pending Created
Processing Provider action
Completed Verified success
Failed Verified failure
Cancelled Cancelled
Refunded Refunded
Provider callbacks are not treated as unquestionable truth. PrimePay performs server-side provider verification before allowing a payment to reach a verified completed state.

Important integration rule

Your application should treat the webhook and payment status as authoritative PrimePay state, rather than assuming that a successful HTTP response from the payment creation request means the customer's money has been received.

Idempotency

Payment creation requires an Idempotency-Key. This prevents duplicate payment creation when a client retries a request because of a network timeout or interrupted connection. 

Idempotency-Key: order-1001-attempt-1

Same key + same request

PrimePay replays the existing payment response instead of creating a second payment. 

{
  "success": true,
  "idempotentReplay": true
}

Same key + different request

Changing the request payload while reusing an existing idempotency key is rejected as a conflicting request.

Generate a new idempotency key for a genuinely new payment. Do not generate a new key merely because the original request timed out.

Webhook Signing

PrimePay signs webhook deliveries using HMAC-SHA256. The signature is calculated from the timestamp and exact request payload.

Signature header

X-PrimePay-Signature: t=TIMESTAMP,v1=SIGNATURE

Signed content

${timestamp}.${rawPayload}

Your webhook receiver should read the raw request body, construct the signed message using the timestamp from the header, calculate HMAC-SHA256 with the webhook secret and compare the resulting signature securely.

Verification example

const crypto = require("crypto");

function verifyPrimePayWebhook(rawPayload, signatureHeader, secret) {
  const parts = Object.fromEntries(
    signatureHeader.split(",").map(part => part.split("="))
  );

  const timestamp = parts.t;
  const receivedSignature = parts.v1;

  const signedPayload = `${timestamp}.${rawPayload}`;

  const expectedSignature = crypto
    .createHmac("sha256", secret)
    .update(signedPayload)
    .digest("hex");

  return crypto.timingSafeEqual(
    Buffer.from(expectedSignature),
    Buffer.from(receivedSignature)
  );
}
Do not parse and re-serialize the JSON body before signature verification. Whitespace and serialization changes can alter the signed payload. Verify the raw request body first.

Errors & HTTP Behavior

PrimePay uses HTTP status codes together with JSON responses describing the failure.

Status Meaning
400 Invalid or malformed request
401 Authentication failed or token missing
403 Authenticated but not permitted
404 Resource not found
409 Conflict, including idempotency conflicts
429 Rate limit exceeded
500 Unexpected server error 
{
  "success": false,
  "message": "Human-readable error message"
}

Integration Example

The following example demonstrates the basic pattern for creating a payment from a server-side application.

Node.js

const crypto = require("crypto");

const API_URL = "https://YOUR-PRIMEPAY-HOST/api/v1";

const response = await fetch(
  `${API_URL}/developer/payments`,
  {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "X-API-Key": process.env.PRIMEPAY_API_KEY,
      "X-API-Secret": process.env.PRIMEPAY_API_SECRET,
      "Idempotency-Key": crypto.randomUUID()
    },
    body: JSON.stringify({
      amount: 1000,
      currency: "KES",
      country: "KE",
      provider: "mpesa",
      paymentMethod: "mobile_money",
      customerName: "John Doe",
      customerPhone: "+254700000000",
      description: "Order payment",
      metadata: {
        orderId: "ORDER-1001"
      }
    })
  }
);

const data = await response.json();

console.log(data);

Recommended production flow

1. Create Create the payment with a unique idempotency key.
2. Store reference Persist the PrimePay payment reference against your order.
3. Wait for state Do not assume payment creation means completed payment.
4. Receive webhook Verify the PrimePay signature before processing the event.
5. Verify status Use the payment status endpoint when reconciliation or confirmation is required.
6. Fulfil order Only fulfil the order after your application has accepted the verified completed state.

Security checklist

Never expose an API secret in browser JavaScript.
Use PrimePay API credentials from your server-side environment. Browser applications should communicate with your own backend rather than embedding private PrimePay credentials in frontend code.
Use HTTPS in production.
Webhook endpoints must be HTTPS outside localhost/127.0.0.1 development environments.
Keep idempotency keys stable during retries.
A timeout does not mean that PrimePay failed to create the payment. Retry the same logical request using the same idempotency key.
