Audit & Activity Logs

A sensitive operational console for reviewing activity that can be verified from PrimePay V1. The interface deliberately distinguishes transaction activity from true immutable administrator audit events.

Audit integrity warning This V1 backend does not currently expose a dedicated immutable AuditLog collection or audit-log API. Therefore this page must not claim that a transaction record is proof of who performed an administrative action. Verified transaction activity is shown below, while true administrator audit evidence remains explicitly marked as not yet available.
Sensitive-data handling Audit interfaces can contain identifiers, customer information, provider references and security-relevant metadata. This console minimizes exposure by displaying only fields needed for operational investigation. API secrets, webhook secrets and authentication credentials are never displayed here.

Audit Evidence Model
Four levels of evidence are intentionally separated.
SENSITIVE
01

Verified Activity

Records returned by the backend, such as transactions and their provider references.

02

Operational State

Payment statuses, reconciliation metadata and lifecycle information that describe system state.

03

Security Evidence

API-key lifecycle, webhook integrity and authorization protections implemented by the backend.

04

Immutable Audit Event

Actor, action, target, timestamp and immutable evidence. Not exposed by the current V1 backend.

Sensitive Information Controls
Rules the administrative UI follows when displaying security-sensitive information.
PROTECTED
API secrets Never rendered in audit activity. API-key secrets are shown only once by the credential-management workflow.
Webhook secrets Webhook signing secrets are not included in activity tables, transaction views or audit-style records.
Authentication tokens JWT tokens are never inserted into displayed activity records, detail panels or search indexes.
Passwords User passwords are not exposed through the administrative activity interface.
Customer contact data Customer fields are only shown when supplied by the transaction record and are not treated as administrator identity evidence.
Provider references Provider transaction identifiers may be shown for reconciliation and investigation, but they are not treated as authentication secrets.
